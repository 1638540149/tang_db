**本次核验对验收脚本做的三处校准(都是 harness 口径,不动产品代码,已写进脚本注释与报告头)**

| # | 改动 | 原因 |
|---|---|---|
| 1 | `memtable_size` 32MB → **2MB**;导入批 5000 → **800** | 32MB 下批量导入受 `Engine.Commit` 的 O(行数 × memtable 条目数) 影响,5000 行批必超 5 秒客户端期限,拿不到可信数字。根因与修复见 **SPEC-P6.1 §1**(已立补丁规约) |
| 2 | 所有 CLI 调用加 `timeout 180`;无界 `wait` 换成 `wait_bounded` | 编码 agent 那一轮实测因无界 `wait` 停在同一处 7 分钟(后台 CLI 在 BE 被杀后不退出) |
| 3 | 10 万行导入重试 6 → 30 次 | CSV 导入幂等续传,重试次数不足会在"数据就绪"断言前就判失败 |

## 5. 两项未达标判定

### 5.1 SC-376:假红(harness 断言正则)

脚本用 `grep -E '^(连接顺序|build=)'` 从 `EXPLAIN` 输出里取两行做前后对比。但 CLI 把计划渲染成表格,每行带 `| ` 前缀,于是匹配数恒为 0 → `before/after` 都是空。

手工探针(`tmp/probe376.sh`,独立端口 9960/9966/9971)真实回显:

```
| 连接顺序: s → b(CBO 重排)                                                 |
| 连接: Sort-Merge Join(两侧已按连接键有序) / b 左侧估算 rows=2,右侧 rows=3 |
| build=左(按估算行数,FR-637)                                               |
| 列: 读取 5 / 表 5 列                                                      |
| 估算: rows=3, cost=3.0                                                    |
| 依据: 统计(t=2026-10-28 16:22:29)                                         |

# 保留脚本原正则:匹配 0 次
# 去掉行首 "| " 后:两条都命中
```

**判定:产品侧功能正常(CBO 重排 + build 侧 + 列投影 + 估算 + 依据全都有);断言已改为 `sed 's/^| //; s/ *|$//'` 后再 grep。**

### 5.2 SC-387:真未达标(性能门限)

同一脚本内(`CboBench`,同 JVM,三次中位数,单位 ms):

| 查询 | `optimizer_enabled=true` | `false` | 变化 |
|---|---|---|---|
| Q1 | **53** | 68 | **快 22.1%** ✅ |
| Q3 | 157 | 165 | 快 4.8% |
| Q5 | 86 | 104 | 快 17.3% |
| Q6 | 57 | 67 | 快 14.9% |
| Q10 | 120 | 121 | 快 0.8% |

- 硬门限"单条不变慢 >10%" **通过**;但"≥2 条快 ≥20%" **只有 Q1 一条达到**(Q5 差 2.7 个百分点)。
- 原因:验收数据规模小(基表万级),CBO 的收益集中在"选择率差异大 + 有可用索引"的形态;`p6-test` 里的表都太小,统计差异不足以拉开两条以上 20%。
- **门限不改**(规约 §2.1-I 组口径)。处置:记遗留,待 P6.1(执行层性能)与真实规模数据(如 `ecom` 30 万行)上复测;若届时仍不达标,再评估是否把该门限改成"平均"口径——那时要所有者拍板。

## 6. 外部评审必答项(P6 侧)

外部评审挂给"P6/P7"的必答项是**混合查询语义先行**(精确向量检索 → ANN → CBO 选路)。P6 只落代价框架,不实现任何向量能力,规约 §7 已正面回答:

- 访问路径选择表留"向量索引扫描"槽位(P7 注册代价函数),本期该槽位永远不被选中(没有 `VECTOR` 类型);
- ANN 自己的统计(图规模/层数/删除率)由 P7 按同一 `CostModel` 接口上报;
- 混合查询的路径决策**不在 P6**,P6 只保证单表结构化谓词的估算足够准;
- 红线:P6 未为 P7 提前引入 `VECTOR` 类型、`proto` 字段或磁盘格式变化(`proto/` 与 `be/` 本次 diff 为空)。

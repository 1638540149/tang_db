## 7. SC-417 既有回归:嵌套链不稳,单跑取数

### 7.1 本轮一键脚本的嵌套结果(不采信的部分也如实列出)

`p6.1-test.sh` 的 SC-417 是**串行调用** `p2 → p3 → p35 → p4 → p5 → p6 → crash-test`,每个脚本内部**又各自嵌套**别人的回归(p35 调 p3、p3 调 p2、p4 调 p2/p3/p35、p5 调 p2/p3/p35/p4、p6 调 p2/p3/p35/p4),最深处是 `p6.1 → p6 → p4 → p3 → crash-test` 五层。本轮结果:

| 脚本 | 嵌套结果 | 红在哪 |
|---|---|---|
| p2-test | **PASS=52 FAIL=0** | — |
| p35-test | **PASS=44 FAIL=0** | — |
| crash-test | **全绿,丢失 0 条** | — |
| p3-test | FAIL | 3 条:注入点 after_memtable(2)+ SHOW BACKENDS 心跳(2) |
| p4-test | FAIL | 自身 186 PASS / 1 FAIL —— 那 1 条就是它内部嵌套的 p3 |

三次 p3 失败**每次都不一样**(3 条 / 2 条 / 3 条,失败项从"注入点 after_memtable"换到"WAL 截断后只剩第一条"),而同一条 p3 在 09:41 那次(p35 里)是 **63/0 全绿**。失败项随嵌套位置漂移、不是同一处代码反复判错,这是典型的环境/时序污染(上一层刚杀掉的 BE 端口未释放、心跳端口被上一轮 CLI 占着),不是产品回归。

## 七、这份代码的坑(读的时候会绊到)

1. **盐必须是无 `0x00` 的可打印 ASCII**(20 字节)。Connector/J 会把 part-2 当 NUL 结尾字符串、并在 String 与 byte[] 之间往返 —— 非 ASCII 或含 `0x00` 都会坏握手。改 `NativePassword.randomSeed` 前先看这条。
2. **`stripLeadingComments` 必须在 `Parser` 之前**。JDBC 连接期会发 `/* 5.7.99 */ SELECT @@version` 之类;少了这一步就是"第 1 行第 1 列无法识别的字符 '/'"。
3. **包序号的三个重置点**:握手 `setWriteSeq(0)`、认证通过后 `setWriteSeq(2)`、命令应答 `setWriteSeq(1)`。错一位客户端就"卡在握手/结果集不全"。
4. **`Executor` 是每会话一个**,`currentDatabase` 与事务写集都挂在它身上 —— 别把 Executor 做成单例,否则会话隔离立刻破。
5. **`Result.Table` 仍全量驻留内存**(承 P2/P3)。协议层按行写包只是"发送侧流式",大结果集的内存上限要等 P8。
6. **`SessionManager.register` 抛的是 `SqlError`(1040)**,不是 `IOException` —— 握手阶段拒绝要在 `ConnectionHandler.authenticate` 里转成 ERR 包再断开。
7. 测试脚本全在 `scripts/tests/`,内部 `ROOT_DIR` 是 `../..`;新加脚本别照抄 `scripts/` 下面的相对层级。
8. `p35-test.sh` / `p3-test.sh` 都会 `taskkill` 所有 `be.exe` 与 `fed` 进程 —— **不要和别的会话(尤其编码 agent)同时跑**。

## 八、建议的阅读顺序(约 40 分钟)

1. `fed/Fed.java` → 知道进程骨架。
2. `protocol/mysql/ConnectionHandler.java` → 一轮完整的"握手 + 一条 SQL"。
3. `execute/SqlEngine.java` → 兼容层到底兜了什么(这是本期最"脏"也最关键的一层)。
4. `catalog/Catalog.java` 的 `createDatabase` / `loadDatabases` / `decodeTableRowTolerant` → 多库 + 老目录升级。
5. `catalog/SystemTables.java` → 系统表领号规则。
6. `protocol/mysql/MysqlClientConnection.java` + `client/Cli.java` → 客户端这一侧。
7. 最后回头看 `scripts/tests/p35-test.sh` 的 SC-301~SC-318 分段,对着代码验一遍断言。

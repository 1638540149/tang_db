## 1. 环境纪律(违反则结果不可信)

- **独占**:同一时刻只允许一个测试脚本在跑。开跑前确认没有残留 `be.exe` / `tangdb.fed.Fed`:
  `ps -W | grep -iE 'be\.exe|java\.exe'` 与 `netstat -ano | grep LISTENING | grep -E ':(9900|9906|9991|9716|9940|9946|9951|9110)\s'`

- **起服务只用仓库脚本**:`scripts/start-be.sh` / `scripts/start-fe.sh` / `scripts/tests/*.sh`;禁止 `nohup` / `disown` / 裸 `&`(上一轮这样把 bash 工具卡死三次)。单条命令超过 90 秒没返回就换写法。
- 端口/数据目录不要改成业务环境的 9100/3406;脚本各自带端口。

## 3. 本轮 5 条 FR 的定向验证(重点,必须自己设计查询)

| FR | 怎么证它生效 |
|---|---|
| FR-716 解码复用 | 同一张 20 列表,`SELECT *` 与 `SELECT 两列` 各跑 N 次:结果逐行一致;并记录 GC/分配情况(可用 `-verbose:gc` 日志条数或对比耗时) |
| FR-714 并行排序 | 大表 `ORDER BY 多列` + `LIMIT`:并行度 1 与 8 的**结果逐行一致且顺序一致**,并行度 8 更快 |
| FR-713 聚合并行 | `GROUP BY` + `COUNT/SUM/AVG/MIN/MAX/STDDEV/VARIANCE/GROUP_CONCAT`:并行度 1 与 8 **逐行一致(含行序)** |
| FR-712 Hash Join 并行 | 三表 JOIN(含 `LEFT JOIN` 的补空行):并行度 1 与 8 逐行一致;8 更快 |
| FR-715 结果流式 | `SELECT * FROM 宽表 LIMIT 10` 与 `LIMIT 5 OFFSET 100`:行数/内容与关闭流式时一致;大结果集(≥20 万行)不 OOM |

对每条给出:命令、SQL、并行度、耗时(三次中位数)、结论(生效 / 没生效 / 生效但有副作用)。

## 1. 事实(核验方实测,不是推测)

| 项 | 实测 | 门限 |
|---|---|---|
| SC-431 纯向量检索 top-10(10 万行 × 128 维) | **RUNS=[1019, 579, 613],中位 613ms** | ≤ 100ms |
| SC-427 8 线程并发检索 P99 / 空载 P99 | 575ms / 144ms = **4.0×** | ≤ 2× |
| 同一数据改 `k` | k=10 **774ms**;k=100 **765ms**;k=500 **2993ms** | — |
| 退化告警 | BE 日志无"退化为暴力" | — |

**k=10 与 k=100 几乎同耗** ⇒ 存在一笔与候选数无关的**固定开销(约 600~700ms/查询)**;只有 k 很大、`ef` 跟着涨时才体现候选量成本。

## 2. 范围

### 2.1 本期做

**A 组 · 固定开销剖析与消除(FR-791 ~ FR-796)**

- 先用**计时打点**证明钱花在哪(不许凭猜改):候选准备、图搜索、memtable 暴力、候选回表、FE 打分五段各自耗时,写进日志或 `EXPLAIN` 的可选行。
- 重点怀疑(需逐一排除或确认):`runtimeFor` 的 `extractVectors` **每次查询整列回读**(10 万 × 128 维 ≈ 51MB);`bruteForceMemtables` 每查询全扫 memtable/immutable;候选回表是否逐 key 发请求。
- 消除手段(按代价从低到高):
  1. 图运行时的向量缓存**常驻**(加载一次,按 `bytes` 计数,超预算按 LRU 淘汰),而不是每次查询重建;
  2. 若常驻不可行,检索时**只按 `rowOrdinal` 点读需要的候选行向量**,不整列回读;
  3. memtable 侧只扫 snapshot 内可见且未落盘的行,不做无谓的全量解码。
- 目标:`10 万 × 128 维 top-10` 中位 ≤ 100ms(SC-431 门限不变)。

**B 组 · 候选取回与打分(FR-797 ~ FR-800)**

- 候选回表**一次批量请求**(一次 `BatchGet` 带全部候选 key),禁止逐 key 一发;
- FE 侧精确打分只对**归并后的 ef 个候选**做一次,不重复解码整行;
- 候选集合用**紧凑结构**(行键 + 距离),不许 `map[string]` 做中间归并(10 万级会拖慢)。

**C 组 · 并发退化(FR-801 ~ FR-804)**

- 8 线程并发检索 P99 ≤ 2× 空载(SC-427 门限不变);
- 每查询**不得**在 `vec.mu` / `e.mu` 上做长临界区:运行时快照按索引取一次引用,后续只读;
- 每段图搜索可并发(段之间无共享写);候选归并加锁范围限制在本地结构;
- 并发下不得因缓存淘汰抖动导致时延尖刺(淘汰策略要稳定)。

**D 组 · 路径 A 走图(FR-805 ~ FR-808)**

- P7 的路径 A 是"先物化允许集 → 允许集内精确打分"(验收报告 §7 记的偏差);本期改为**允许集下推**:把允许集(主键集合,超阈值换布隆)交给图检索,`Search` 在允许集内展开候选;
- 允许集不可用/过大时按 K167 退回路径 B,行为不变;
- 两条路径结果**逐行一致**这条不许破(SC-422)。

**E 组 · 门限与回归(FR-809 ~ FR-812)**

- `p7-test.sh` 增加"分段耗时"输出(可关),便于以后一看就知道钱花在哪;
- 新增 `p7-perf.sh`:固定 10 万 × 128 维,输出导入/建图/检索三段耗时与 P50/P99,供回归对比;
- ★ 回归:本期改的是检索路径,必须重跑 `p7-test.sh` + `p7-recall.sh` + `p3-test.sh` + `p4-test.sh` + `p6.1 iso 本体`,全绿才算完。

## 3. 关键决策(K 表,续排)

> 编号续排:上期最大 K177,本期从 **K178** 起。

| 编号 | 决策点 | 推荐值 | 理由 |
|---|---|---|---|
| K178 | 向量运行时缓存 | **常驻 + 按字节预算 LRU 淘汰**(默认预算 = 内存的 10%,可配 `vector_cache_bytes`) | 固定开销的根源就是每次重建;常驻后查询只做图搜索 |
| K179 | 缓存淘汰稳定性 | 淘汰按"段访问时间 + 引用计数",检索期间被引用的段不淘汰 | 避免并发下降级抖动(SC-427 的尖刺) |
| K180 | 候选回表 | **一次 `BatchGet` 批量取全部候选**(上限 = `ef`) | 逐 key 一发的 RTT 成本在 128 维下不可接受 |
| K181 | 打点粒度 | 五段计时写入 debug 日志 + `EXPLAIN` 可选行(`SET vector_profile = ON`) | 不污染默认输出,又能复现 |
| K182 | 路径 A 允许集 | **主键集合 ≤ 1 万,超了用布隆**;空集直接返回空 | 与 K168 一致,本期只把"下推到图内"补齐 |
| K183 | 并发模型 | 段级并行 + 只读快照,临界区只保护缓存表 | 8 线程下不因全局锁排队 |
| K184 | 性能脚本口径 | 同 JVM、三次中位数、安静机;报 P50/P99 与分段耗时 | 避免再出现"CLI JVM 启动算进指标"的口径问题 |

## 5. 边界与异常(续排,从 155 起)

| # | 边界 | 期望行为 |
|---|---|---|
| 155 | `vector_cache_bytes` 小于单段向量总量 | 允许,但必须走"按候选点读"路径,结果不变、时延可接受 |
| 156 | 缓存淘汰与正在检索的段冲突 | 该段引用计数 > 0 时不淘汰 |
| 157 | 允许集为空 | 直接返回 0 行,不发起图检索 |
| 158 | 允许集全命中 | 退回路径 B(K167 阈值),`EXPLAIN` 说明 |
| 159 | 候选回表部分 key 已删 | 丢弃,不影响其它候选 |
| 160 | 并发检索 + 后台建图 | 检索用旧图/旧缓存,不阻塞、不返回半图结果 |
| 161 | 打点开启时并发 8 线程 | 日志不得成为瓶颈(限流),关掉后行为一致 |
| 162 | 段数很大(≥20) | 段级并行度收敛到 `query_parallelism`,不无限起线程 |
| 163 | k 很大(1,000 上限) | 仍返回正确条数,时延允许线性上升,但不得超时 |
| 164 | 缓存预算非法(0 / 负数 / 超内存) | 启动失败并指出第几行(与既有配置同口径) |
| 165 | 精确模式 + 大表 | 走暴力,`EXPLAIN` 标明;不计入 SC-431 门限 |

## 6. 兼容性边界

- **不新增保留字**;`SET vector_profile = ON|OFF` 是新会话变量(与既有 `SET vector_exact` 同族)。
- **不动磁盘格式**:`format_version` 仍 3,图段布局不变,老目录照旧可启动(无需迁移)。
- **不动 `proto` 既有字段语义**;若需加打点字段,只加可选字段 + 重生成两侧桩。
- 语义等价:`pushdown` / `vector_exact` / `vector_path` 三个既有开关行为不变。

## 实现顺序(每完成一步,立刻跑 `cd fe && mvn.cmd compile` / 相关单测确认没坏)

**步骤 0 · 现状盘点(只读,不改代码)**
在最终输出里先给盘点结论:① 主键 key 怎么拼(`KeyCodec.prefix/rowKey/lowerBound/upperBound`)② `Executor` 的读路径(`forEachMatch` / `Plan.kind`)与写路径(INSERT/UPDATE/DELETE 怎么拼批)③ `Catalog` 的 DDL 批写与启动加载(`loadAll` / `stageTable` / `SysTables` 登记表 / `decodeTableRowTolerant`)④ `SqlEngine.handleCompat` 现在怎么处理 `SHOW` 与 `information_schema`。据此列出要新建/修改的类清单。

**步骤 1 · 索引元数据与 catalog**
- `SystemTables` 新增 `SYS_INDEXES = 5` 并加入 `REGISTERED_IDS`(K70);新 `TableMeta INDEXES`:`table_id BIGINT PK` / `index_id INT PK` / `name VARCHAR(64)` / `column_name VARCHAR(64)` / `is_unique BOOLEAN` / `state INT` / `build_cursor VARCHAR(256)` / `created_at VARCHAR(64)`;key = `table_id 4B BE + index_id 4B BE`(FR-479)
- 启动时**幂等创建** `sys_indexes`(老目录直接可用,`format_version` 不变,FR-478/FR-474)
- `Catalog` 新增索引缓存:`byTable(tableId) → List<IndexMeta>`、`find(tableId, indexId)`、`findByName(db, table, name)`;`createIndex` / `dropIndex` / `updateIndexState` / `updateBuildCursor` 全部走**一次批写**(FR-465/FR-477)
- 索引 ID 分配:`sys_counters` 的 `next_index_id:<table_id>`,每表从 1 起、只增不复用(FR-464/K75)
- 元数据校验:索引指向不存在的表/列、同表索引 ID 重复 → 启动报错指名对象(FR-476);表 dropped 时索引随表不可见(FR-480)

**步骤 2 · 索引 key 编码(KeyCodec 扩展)**
- 二级索引用户键:`[表ID 4B][索引ID 4B][索引列值保序编码][主键值保序编码]`
- 唯一索引用户键:`[表ID 4B][索引ID 4B][索引列值保序编码]`(不含主键),value = 主键值保序编码(K76/§5.2)
- 索引列值编码复用主键保序编码;`VARCHAR` 用 `0x00` 终止,值内含 `0x00` 时按 **K77**(`0x00 0xFF` 转义、`0x00 0x00` 结束)处理,**写路径与读路径必须共用同一函数**(FR-497/FR-521)
- 索引点查/范围的用户键边界(含/不含)由本类统一产出,参照现有 `lowerBound/upperBound` 的 `AFTER_ALL_VERSIONS` 技巧
- 单测:往返编解码、边界包含性、`0x00` 转义、索引值互为前缀时不串区间

**步骤 3 · 索引 DDL 与状态机**
- 语法(§2.1 A 组):`CREATE [UNIQUE] INDEX <idx> ON [<db>.]<tbl>(<col>)`、`DROP INDEX <idx> ON [<db>.]<tbl>`、建表内联 `UNIQUE(<col>)` / `INDEX(<col>)`(FR-456~462);自动命名 `<表>_<列>_idx` / `<表>_<列>_uk`
- 校验:列不存在/主键列/同列重复建/索引名重复(1061)/非法名(FR-457~460);建表内联索引与建表**同一批**(FR-462)
- 状态机 `BUILDING(0) → ACTIVE(1)`、`BUILDING → DROPPED(2)`;不允许 `ACTIVE → BUILDING`(K86);转 `ACTIVE` 的记录**最后写**(FR-470)
- `SHOW INDEXES [FROM <t>]`(FR-471);`DESC` 保持原样(FR-472)

**步骤 4 · 写入路径维护**
- `INSERT`/`UPDATE`/`DELETE` 按 FR-483~FR-497:主键记录 + 每条 `ACTIVE`/`BUILDING` 索引记录**同一批记录**(K89)、同一 `commit_ts`;未改索引列不写(FR-486);同事务改同一行只落最终版本(FR-489);写集按用户键去重(FR-490)
- 唯一校验:同快照下该唯一键已存在且非墓碑 → 整批不写、不取号、报 **1062**(K78/K80,信息含索引名+列名+值+已有主键);并发同一唯一键由 P3 写写冲突(1213)触发,**也翻译成 1062**
- 事务内读己之写:走索引时必须能查到自己未提交的写入(FR-495)
- 单测:多索引同时维护、改索引列(旧项墓碑+新项)、删行墓碑、唯一冲突(单会话/双事务)、超 `max_txn_write_bytes` 整批失败

**步骤 5 · 读路径:索引扫描 + 回表 + 选择规则**
- 等值(FR-498)与范围(FR-499)走索引;回表**同一快照**(FR-500)+ **二次校验**(FR-501:行的索引列值必须等于索引项值,不等就跳过)+ 墓碑跳过(FR-502)
- 残余过滤照旧在 FE 做(FR-503);`LIMIT` 生效(FR-507);`UPDATE`/`DELETE` 的 `WHERE` 同样可走索引(FR-508)
- RBO 规则(K82/FR-504/505):主键等值 > 主键范围 > 索引等值 > 索引范围 > 全表扫;同类多索引取索引 ID 最小者;`OR` 不合并、退化全表扫但**结果必须正确**(FR-506)
- `BUILDING`/`DROPPED` 索引不参与选择、**退化全表扫且不报错**(FR-509/K88)
- 读视图必须仍然走 `ReadView`(FR-510/511);扫描统计(索引项数/回表次数)进日志或 EXPLAIN 摘要(FR-512)
- 单测:索引路径 vs 全表扫逐行对拍、改索引列后旧值查不到、`OR` 退化、`BUILDING` 退化、事务快照一致

**步骤 6 · `EXPLAIN`**
- 语法 `EXPLAIN <SELECT|UPDATE|DELETE ...>`(FR-513),输出**单列结果集**(列名 `plan`,K87)
- 内容:访问路径(`PRIMARY POINT` / `PRIMARY RANGE` / `INDEX POINT` / `INDEX RANGE` / `TABLE SCAN`)、表名、索引名+列、key 范围十六进制摘要、残余过滤条件(FR-514~516)
- **与执行共用同一计划构造入口**,不许另写推算逻辑(FR-517);`EXPLAIN INSERT`/DDL/事务语句明确报不支持(FR-518)

**步骤 7 · 分批回填(建索引的核心难点)**
- 非空表 `CREATE INDEX`:先写 `BUILDING` 元数据 → 分批(默认 1000 行,配置 `index_backfill_batch`)扫全表、每批独立提交写索引记录 + 更新 `build_cursor`(FR-467~468/K84/K85)
- **回填期间的新写入也进索引**(I16/K89),所以转 `ACTIVE` 前**不需要**增量补扫
- 回填中断(强杀/重启)→ 索引仍是 `BUILDING`,重跑同一条 `CREATE INDEX` 能**从游标续做**(FR-469/K86)
- 唯一索引回填时若发现重复 → 索引转 `DROPPED` 并报重复值与前两个主键,不留半成品
- 单测 + 脚本:回填中途强杀 → 重启后 `BUILDING` → 续做完成 → 索引完整

**步骤 8 · 图形客户端元数据自省(F 组,§4.7 / §5.7)**
- Parser 支持 `SHOW` 家族语法(FR-527~536):`FULL TABLES [FROM][LIKE/WHERE]`、`TABLE STATUS`、`CREATE TABLE`、`CREATE DATABASE`、`COLUMNS`/`FULL COLUMNS`、`INDEX`/`KEYS`、`ENGINES`、`COLLATION`、`CHARACTER SET`、`GRANTS`、`TRIGGERS`/`EVENTS`/`ROUTINES`、`VARIABLES`/`STATUS [LIKE]`、`WARNINGS`/`ERRORS`、`FULL PROCESSLIST`

- `information_schema.STATISTICS` / `KEY_COLUMN_USAGE` / `TABLE_CONSTRAINTS` 的数据来自步骤 1 的索引元数据(FR-539);`Cardinality` 恒 `NULL`(§5.7)

## 硬约束(违反即返工)

- BE 侧只允许 `grpc` / `protobuf`;**本期 BE 预期零改动**(非改不可就先停下来在输出里说明理由)。
- FE 侧**不得**引入任何第三方 SQL 解析/索引/协议库;不引 B+ 树/嵌入式索引库 —— 索引就是同一套有序 key。
- FE **不得**读写 BE 数据目录;BE **不得**知道表名/列名/索引/SQL;`proto/` **零改动**。
- 索引记录与主键记录**必须同批、同 `commit_ts`**;写路径顺序不得改动(冲突检测 → WAL → fsync → memtable → 回 OK)。
- 唯一索引的 key **不含主键值**(K76),唯一性靠 P3 的写写冲突,不允许自造锁/预占表。
- `MANIFEST.format_version` 不变;老数据目录**宽容读**(缺 `sys_indexes` 就幂等建)。
- `information_schema` 虚拟表**纯内存**,不得访问 BE;`ORDER BY`/`COUNT(*)` **只准在虚拟表上生效**(K98)。
- 本机口径:`mvn` 一律 `mvn.cmd`;Go 在 `/c/Program Files/Go/bin`;跑脚本前确认没有残留 `be.exe` / `fed` 进程;不要与其它会话同时跑脚本。
- **不要执行 `git commit` / `git push`**;不要写 `docs/验收报告/P4-验收报告.md`、`docs/读代码地图/读代码地图-P4.md`(核验方写),你只负责代码、测试、脚本、README。

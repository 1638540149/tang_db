## 1. 目标

一句话:**让 MySQL 习惯的三种写法在 P2 上能用 —— `` `列名` ``、`INSERT INTO t VALUES(...)`、`SHOW DATABASES`。**

依据(2026-10-23 实机测试记录,逐条对应):

| 测试记录条目 | 现象 | 本补丁的处置 |
|---|---|---|
| 第 2、21~27 条 | `` create table student(`id` INT primary key, ...) `` → 「无法识别的字符 '`'」 | §4.1 反引号标识符 |
| 第 4 条 | `insert into student values(1, 'zhangsan')` → 「期望 列名列表的 '('」 | §4.2 省略列名列表 |
| 第 1 条 | `show Databases` → 报错 | §4.3 `SHOW DATABASES` |
| 第 5~14 条 | `NOT` / `NOT IN` / `BETWEEN` / `LIKE` / `IS [NOT] NULL` 全部报「这里需要一个比较运算符」 | §6 定归属(**不在本补丁做**) |
| 第 3、15~20、29~31 条 | `ALTER TABLE`、`= NULL` 返回 0 行、`UPDATE SET 主键` 被拒、`ORDER BY` / 聚合 / 表达式 | 已符合 P2 规约或排期在后,**不改**(见 §2.2) |

## 4. 功能需求

### 4.1 反引号标识符

- **FR-180** 词法分析器识别 **用反引号包裹的标识符**,产出一个专门的标识符 token;`` `id` `` 在**所有接受标识符的位置**等价于普通标识符:表名、列名、列别名(`AS` 后)、`DESC` 目标、`INSERT` 列名列表、`UPDATE` 的 `SET` 列、`WHERE` 里的列名。
- **FR-181** 反引号内的文本**一律按标识符**处理,不做关键字解释 —— 因此 `` `select` ``、`` `from` ``、`` `values` ``、`` `order` `` 都能当列名/表名使用。
- **FR-182** 反引号**不引入大小写语义**:`` `ID` ``、`` `id` ``、`ID`、`id` 是同一个名字(沿用 K21,内部统一小写)。
- **FR-183** 反引号内允许**除反引号本身以外的任意字符**,包括空格、中划线、中文、数字开头;不新增名字长度限制。
- **FR-184** 反引号内的**双写反引号**表示一个反引号本身(MySQL 习惯):形如 `` `a``b` `` 的写法,得到的是 a、反引号、b 三个字符拼成的名字。
- **FR-185** 错误提示(必须可读、必须带位置):
  - 未闭合的反引号 → `标识符缺少结束的反引号`;
  - 空的反引号(两个反引号之间没有任何字符)→ `标识符不能为空`;
  - **不得**再出现「无法识别的字符」+ 反引号 这类提示(见场景 3)。
- **FR-186** 反引号**不能**用来包裹语句关键字与列类型:`` `select` * from t `` 与 `` `INT` `` 一律按原样报语法错误(不允许用反引号绕开语法结构)。
- **FR-187** 多行输入缓冲(`SqlBuffer`)必须把反引号与单引号**同级**处理:反引号内的 `;` 不算语句结束;反引号未闭合时继续等待输入(续行提示符不变)。

### 4.2 INSERT 省略列名列表

- **FR-190** `INSERT INTO <表> VALUES (v, ...) [, (v, ...)]*` 合法:目标列取**表定义顺序的全部列**。
- **FR-191** 省略形式必须给全所有列的值;某组值个数与列数不符 → 报错并指出**第几组**(沿用现有文案:`第 k 组取值个数(M)与列数(N)不一致`),不写半行数据。
- **FR-192** `INSERT INTO <表> () VALUES (...)`(空列名列表)→ 报错 `列名列表不能为空`。空列表因而只有"省略形式"一种来源。
- **FR-193** 显式列名形式(FR-130)行为**完全不变**,未给出的列仍写 NULL;两种形式可在同一表、同一会话内混用。

### 4.3 SHOW DATABASES

- **FR-200** 新增 `SHOW DATABASES`:输出表格,列头 `Database`,一行 `default`(K22:只有默认库)。
- **FR-201** 该语句由 FE 内存 catalog 直接回答,**不访问 BE**;BE 不可用时它照样出结果(与 `SHOW TABLES` 现状一致)。
- **FR-202** 关键字大小写不敏感;`SHOW` 后面不是 `TABLES` / `DATABASES` 时,报 `SHOW 只支持 SHOW TABLES / SHOW DATABASES`。
- **FR-203** CLI 的用法提示行(`USAGE` 与启动横幅)与 README 的示例同步列出新增写法。

### 4.4 不改的东西(硬性)

- **FR-210** 不新增保留字;除"反引号由报错变合法"外,现有合法输入的解释一律不变。
- **FR-211** 不改 `proto/tangdb.proto`、不改 BE、不改 key/value 编码与系统表布局(`sys_tables` / `sys_columns` / `sys_counters` 原样)。
- **FR-212** 不引入任何第三方依赖(宪法:BE 只允许 grpc / protobuf;FE 不得引第三方 SQL 解析库)。
- **FR-213** 不实现 §2.2 里"本期不做"的任何能力;遇到这些写法按现有方式报错,不得偷偷放行。

## 6. 谓词与查询能力的归属结论(正面回答测试记录 5~14 条)

测试记录里 `NOT` / `NOT IN` / `BETWEEN` / `NOT BETWEEN` / `LIKE` / `IS [NOT] NULL` 全部报
「这里需要一个比较运算符」,以及 `= NULL` 查不到 NULL 行 —— 这是**规约缺口**:SPEC-P2 §4.5 FR-141
只列了「比较 + AND/OR + 括号 + IN」,§2.2 又只把 `ORDER BY`/聚合/子查询明确排给 P5,**谓词这一批没写归属**。
现正面定死:

| 能力 | 归属期次 | 理由 |
|---|---|---|
| `IS [NOT] NULL` | **P5** | NULL 三值逻辑的完整语义(与 `= NULL` 的区别、UNKNOWN 传播)应和 P5 的谓词体系一次讲清 |
| `NOT`(一元)与 `NOT IN` | **P5** | 一元取反要给出三值真值表,不能只做布尔取反 |
| `LIKE`(含 `%`、`_` 与转义) | **P5** | 通配符语义、大小写口径、转义字符都是要独立定的语义面 |
| `BETWEEN ... AND ...` | **P5** | 语法糖(等价 `x >= lo AND x <= hi`),但涉及边界包含与 NULL 传播,随 P5 一起定 |
| `ORDER BY` / `OFFSET` / `LIMIT m, n` | **P5** | 承 SPEC-P2 §2.2 |
| 表达式与标量函数 | **P7** | 承 SPEC-P2 §2.2 |
| `ALTER TABLE` | **P4 之后** | 承 SPEC-P2 §2.2 |

**P5 立规约时必须逐条给出**(现在先记着,免得 P5 又漏):

1. 三值逻辑完整真值表(含 `NOT UNKNOWN`、`UNKNOWN AND FALSE` 这类);FE 侧 `Predicate` 已按三值实现,继续沿用。
2. `IS NULL` 与 `= NULL` 的区别,以及在 CLI/README 里明说"查 NULL 行必须用 `IS NULL`"(测试记录第 15、16 条正是这个直觉坑:`= NULL` / `<> NULL` 恒返回 0 行,**是标准行为,不是 bug**)。
3. `LIKE` 的 `%` / `_` 语义、转义字符、与 `VARCHAR` 字节序的关系。
4. `BETWEEN` 两端**都包含**(闭区间)。
5. `IN` 列表里含 NULL 时的结果(`In` 谓词现有实现已返回 UNKNOWN,需在规约里写明)。

> 本补丁**不实现**上表任何一条(FR-213)。测试记录第 5~14 条因此**在 P2.1 之后仍然报错**,这是按计划,不是漏修。

## 7. 关键技术决策(本期默认值)

已按推荐取值,写进规约作为施工默认。**有异议请指出,没异议就照办。**

| # | 决策点 | 取值 | 理由 |
|---|---|---|---|
| K31 | 反引号是否改变大小写语义 | **不改变**(仍统一小写,K21 不变) | 一个库里两套大小写规则最容易出"为什么查不到"的坑 |
| K32 | 反引号内允许的字符 | **除反引号外任意字符**(含空格、中划线、中文、数字开头) | 规则最少:"反引号里的东西原样是名字";代价是 `SqlBuffer` 多跟踪一个状态位(FR-187) |
| K33 | 反引号转义 | **双写反引号 = 一个反引号** | MySQL 习惯,实现约 3 行 |
| K34 | 反引号能否包语句关键字 / 列类型 | **不能**,按原样报语法错误 | 允许的话文法要变成"关键字可被引用",复杂度不值 |
| K35 | INSERT 省略列名的语义 | **按表定义顺序取全部列**;只支持全列,不支持部分列 | 与 MySQL 一致;部分列会有"缺的列写 NULL 还是报错"的二义 |
| K36 | `SHOW DATABASES` 输出 | 单列 `Database`,一行 `default`;不访问 BE | 只有默认库(K22),静态回答最快也最稳 |
| K37 | 谓词(NOT / IS NULL / LIKE / BETWEEN)落点 | **全部归 P5**,本补丁不做 | 查询语义一次定清,拆开做会返工;详见 §6 |
| K38 | 空列名列表 `()` | **报错**,不解释成"零列" | 让"省略形式"成为空列表的唯一来源,实现无二义 |

> K37 的备选(想改就一句话):若你希望**本期就能查 NULL 行**,可把 K37 改成
> 「`IS [NOT] NULL` 归 **P2.1**,其余谓词仍归 P5」—— 这一条改动不影响到其余条目。

## 9. 边界与异常清单

| 情形 | 期望行为 |
|---|---|
| 反引号未闭合 | 报 `标识符缺少结束的反引号` + 位置 |
| 反引号内含单个反引号(非双写) | 视为标识符结束(与 MySQL 一致) |
| 空反引号(两个反引号之间无字符) | 报 `标识符不能为空` |
| 反引号内出现 `--` | 当作名字的一部分,**不是注释** |
| 反引号内含 `;` | 不结束语句(`SqlBuffer` 同步跟踪,FR-187) |
| 反引号跨行未闭合 | 继续等待输入(续行);`exit` 时可放弃 |
| `` SELECT * FROM `no_such` `` | 报 `表 no_such 不存在`(与不带反引号一致) |
| `` SELECT `nope` FROM users `` | 报 `列 nope 不存在(表 users)`(与不带反引号一致) |
| 反引号包语句关键字 / 类型名 | 按原样报语法错误(FR-186) |
| `INSERT INTO t VALUES (...)` 少值 / 多值 | 报错并指出第 k 组:`取值个数(M)与列数(N)不一致` |
| `INSERT INTO t () VALUES (1)` | 报 `列名列表不能为空` |
| `INSERT INTO t VALUES ()`(零值) | 报取值个数不一致(除非表恰好 0 列 —— 不可能) |
| 省略形式里某行主键冲突 | 沿用 P2:报主键冲突,已写入的行保留,错误信息说明第几组(SPEC-P2 §8) |
| `SHOW DATABASES` 在 BE 未启动时 | **语句本身**由 FE 内存直接回答,不访问 BE(FR-201);但 CLI 会话仍需要 BE 才能启动(FR-111),故该条**只有单元测试证据**、端到端演示不了 —— 2026-10-23 经项目所有者确认接受此口径 |
| `SHOW DATABASES` 与 `SHOW TABLES` 大小写混写 | 均识别 |
| `SHOW SCHEMAS` / `SHOW DATABASE`(单数) | 报 `SHOW 只支持 SHOW TABLES / SHOW DATABASES` |
| 双引号标识符 `"id"` | 不做(K32/§2.2);报现有语法错误 |

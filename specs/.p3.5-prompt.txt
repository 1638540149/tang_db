## 实现顺序(每完成一步,立刻跑构建/测试确认没坏)

> 关键排序说明(务必理解再动手):规约 K67 规定 **CLI 通过 MySQL 协议连 `fed`,不另造私有协议**。所以协议层的**最小可用子集**(握手 + 认证 + `COM_QUERY` + 文本结果集)必须**先于 CLI 瘦客户端**落地 —— 否则 CLI 无处可连。规约 §2.1 的"第零步 → 第一步 → 第二步"仍成立:第二步做的是协议**扩展**(`COM_INIT_DB`、兼容白名单、错误码收口、切片、`information_schema`、三类客户端实测),不是协议从零开始。

**步骤 0 · 现状盘点(只读,不改代码)**
在最终输出里先给一段盘点结论:① CLI 现在怎么起来、执行链经过哪些类(`Cli` → `parser` → `planner` → `execute` → `storage`/`client`)② catalog 缓存现在归谁持有、心跳端口现在绑在哪个进程 ③ key 编码在哪个类、`sys_tables` / `sys_counters` 的列与 ID 校验写在哪 ④ P2/P3 的测试脚本怎么起 CLI。据此列出你要新建/修改的类清单。

**步骤 1 · 会话层与执行入口抽取(纯重构,行为不变)**
- 新建 `fe/src/main/java/com/wangyu/tangdb/session/`:`Session`(id / 连接源 / 当前库 / 当前事务 / 写集 / 开始时间 / 空闲计时)、`SessionManager`(创建、登记、`session_max`、`session_idle_timeout`、优雅退出等待)

- 本步不改对外行为:跑 `cd fe && mvn.cmd test`,P1~P3 全部用例必须仍绿

**步骤 2 · MySQL 协议最小子集(必须先于 CLI)**

## 硬约束(违反即返工)

- BE 侧**只允许** `google.golang.org/grpc` 与 `google.golang.org/protobuf`;**本期 BE 预期零改动**(若你认为非改不可,先停下来在输出里说明理由,不要擅自改)。

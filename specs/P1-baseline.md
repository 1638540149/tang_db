## 1. 目标

一句话:**在命令行敲一条 `put`,数据真正落到磁盘;把两个进程全部强杀,重启后数据还在。**

P1 不做任何业务功能,不做 SQL,不做表。它只解决一件事:**这套存储与链路,是不是真的可靠。**

这是整个项目的地基。地基建歪了,后面七期全部白做。

| 不做 | 归属 |

## 3. 用户场景与验收(BDD)

### 场景 1:写入并读回(P1,基线能力)

```
Given  BE 已在 127.0.0.1:9100 启动,数据目录为空
And    FE 命令行客户端已连上 BE
When   执行 put name wangyu
Then   返回 OK
And    执行 get name
Then   返回 wangyu
```

### 场景 2:数据落盘(证明不是只存在内存里)

```
Given  已执行过若干次 put
When   查看数据目录
Then   目录下存在 wal/ 与 sst/ 子目录
And    wal/ 下有 .wal 文件且大小非零
And    当写入量超过 memtable 阈值后,sst/ 下出现 segment 文件
```

### 场景 3:★ 强杀重启后数据仍在(P1 的核心验收)

```
Given  已写入 1000 条随机 key/value,每条都返回过 OK
And    FE 与 BE 进程都在运行中
When   用 kill -9(或 taskkill /F)强杀 FE 与 BE 两个进程
And    重新启动 BE
And    逐条 get 这 1000 个 key
Then   1000 条全部读回,值与写入时完全一致
And    丢失条数 = 0
```

### 场景 4:memtable 阈值触发刷盘

```
Given  memtable 阈值设为较小值(如 1MB,便于测试)
When   持续写入直到超过阈值
Then   当前 memtable 被冻结
And    后台生成一个 segment 文件
And    新写入进入新的 memtable
And    ★ 刷盘期间写入不被阻塞(可继续 put 并返回 OK)
```

### 场景 5:读跨越内存与磁盘

```
Given  某个 key 在较早写入(已刷入 segment 文件)
And    另一个 key 刚写入(只在 memtable 里)
When   分别 get 这两个 key
Then   两者都能正确读回
```

### 场景 6:WAL 尾部被截断时能正常恢复

```
Given  BE 已停止
And    手工把 wal 文件最后若干字节截掉(模拟崩溃时的半条写)
When   启动 BE
Then   BE 正常启动,不崩溃
And    截断那条记录被丢弃
And    该记录之前的全部数据都能读回
```

### 场景 7:key 不存在

```
Given  key "not-exist-key" 从未写入
When   get not-exist-key
Then   返回 NOT_FOUND
And    客户端明确显示"键不存在",而不是显示空值或报"成功"
```

### 场景 8:FE 连不上 BE

```
Given  BE 未启动
When   启动 FE 并执行 get name
Then   FE 给出明确错误提示(如"无法连接 BE 127.0.0.1:9100")
And    不挂起、不崩溃、不打印 Java 异常堆栈给用户
```

## 4. 功能需求

### 4.1 接口

- **FR-001** BE 必须实现 `proto/tangdb.proto` 中定义的全部三个 RPC:`Ping` / `Put` / `Get`。
- **FR-002** `Put` 成功返回 `OK` 的前提是:该次写入的 WAL 记录已经 `fsync` 到磁盘。**不允许先返回 OK 再落盘。**
- **FR-003** `Get` 在 key 不存在时返回 `NOT_FOUND`,不得返回 `OK` + 空值。
- **FR-004** key 为空(`len == 0`)时返回 `INVALID_ARGUMENT`。
- **FR-005** key 与 value 均为任意字节序列(含 `\0`、非 UTF-8 内容),不得做字符集假设。
- **FR-006** 单个 value 上限 1MB;超过返回 `INVALID_ARGUMENT`。
- **FR-007** FE 与 BE 之间**只**通过 gRPC 通信;FE 不得读写 BE 数据目录下的任何文件。

### 4.2 写入路径(顺序不可调换)

- **FR-008** 一次 `Put` 的处理顺序固定为:① 组装并追加 WAL 记录 → ② `fsync` → ③ 写入 memtable → ④ 返回 OK。
- **FR-009** 任一环节失败(如磁盘满)必须向客户端返回 `INTERNAL` 与明确信息,且**不得**让内存与磁盘产生不一致。
- **FR-010** WAL 记录必须包含 CRC32C 校验字段与载荷长度,格式见 §5.2。

### 4.3 内存表与刷盘

- **FR-011** MemTable 使用**跳表**实现,key 有序;支持多线程并发插入。
- **FR-012** memtable 达到阈值(默认 64MB,可经 `--memtable-size` 配置)后冻结为只读,并另起新表继续接受写入。
- **FR-013** 冻结的表由**后台 Flush Worker**写成 segment 文件;**刷盘期间前台写入不得被阻塞**。
- **FR-014** 同一时刻最多允许一定数量的不可变表(建议 2 个);超出时前台写入需要等待——此策略须在代码注释中写明。
- **FR-015** segment 文件写完、并原子更新 MANIFEST 之后,对应的 WAL 才可被回收。**顺序不可反。**

### 4.4 读取路径

- **FR-016** `Get` 的查找顺序固定为:MemTable → 不可变 MemTable(若存在)→ Segment(按新到旧)。**任一环节命中即返回,不得继续往下找。**
- **FR-017** 在 segment 内查找时,必须先用 ZoneMap / Index Block 缩小范围,再读数据块;不得整文件顺序扫描。

### 4.5 文件与恢复

- **FR-018** segment 文件格式见 §5.3;文件一旦落盘即**不可修改**。
- **FR-019** MANIFEST 记录当前有效 segment 列表与当前 WAL 编号,更新必须是原子动作(写临时文件 + rename)。
- **FR-020** 启动恢复流程固定为:读 CURRENT → 读 MANIFEST → 校验并加载 segment → 重放 WAL。
- **FR-021** WAL 重放时逐条校验 CRC32C;遇到校验失败或不完整的记录,**在此处停止并丢弃其后内容**,而不是报错退出。
- **FR-022** 恢复完成后 BE 才开始对外提供服务;恢复进度须打印到日志。
- **FR-023** MANIFEST 引用了但磁盘上缺失/损坏的 segment,**不得**导致启动失败;应跳过并记警告。

### 4.6 启动与配置

- **FR-024** BE 的启动配置来自 **`config/be.conf`**(与 `fe/`、`be/` 同级),键为 `data_dir`(默认 `./data/BE`)、`port`(默认 `9100`)、`memtable_size`(默认 `64MB`)。FE 的启动配置来自 **`config/fe.conf`**,键为 `be_host`(默认 `127.0.0.1`)、`be_port`(默认 `9100`)。格式见 §5.5。
- **FR-024a** 取值优先级固定为:**命令行参数 > 配置文件 > 内置默认值**。命令行参数只覆盖显式给出的那一项,其余仍以配置文件为准。
- **FR-024b** 未显式指定 `--config` 时,按默认路径 `./config/be.conf` / `./config/fe.conf` 查找;默认路径不存在则退回内置默认值并打印警告。**显式指定 `--config` 而文件不存在,必须启动失败(退出码非 0)**,不得静默使用默认值。
- **FR-024c** 配置文件里出现未知配置项、格式错误、取值非法(端口越界、容量非法等)时,必须**启动失败并指明文件名与行号**;不得静默忽略。
- **FR-024d** 启动日志必须打印**生效配置的来源路径**与最终取值(数据目录、端口、memtable 阈值),便于排查"到底读的哪份配置"。
- **FR-025** 数据目录不存在时自动创建(含 `wal/`、`sst/`)。
- **FR-026** 端口被占用时,打印明确错误并退出(退出码非 0),不要静默重试或换端口。
- **FR-027** BE 启动完成须打印:数据目录、监听地址、memtable 阈值、恢复统计(加载了几个 segment、重放了多少条记录)。

### 4.7 客户端

- **FR-028**(**0.3 修订**;原 0.1 版要求 `put <key> <value>` / `get <key>` / `ping` / `exit`)FE 的命令行定位是 **SQL 控制台 + 探活**:只保留 `ping`(探活,`scripts/crash-test.sh` 依赖它判断 BE 是否就绪)与 `exit`;`put` / `get` 两个**裸 KV 命令不再提供** —— 从 P2 起读写一律走 SQL。若将来确需调试用的裸 KV 存取,另立条目讨论,不要顺手加回。
- **FR-029**(**0.3 修订**)本条目随 FR-028 废止:`put` / `get` 已不提供,key/value 的编码语义由 SQL 层的编码规约承接(SPEC-P2 §5 与 SPEC-P3 §5)。
- **FR-030** FE 连不上 BE 时给出中文明确提示,不打印 Java 堆栈。

## 5. 数据与文件格式

### 5.1 数据目录

```
<data-dir>/
├── CURRENT                 内容:当前 MANIFEST 文件名(如 MANIFEST-000007)
├── MANIFEST-000007         版本记录:有效 segment 列表 + 当前 WAL 编号
├── wal/
│   └── 000012.wal          预写日志
└── sst/
    └── 000045.seg          segment(列式)
```

> `vecidx/`、`meta/` 本期不创建(留待 P7、P2)。

### 5.2 WAL 记录格式

```
┌──────────┬────────┬──────────┬─────────────────────────────────────┐
│ CRC32C   │ 类型   │ 载荷长度 │ 载荷                                 │
│ 4 字节   │ 1 字节 │ 4 字节   │ key_len(4) | key | value_len(4) | value│
└──────────┴────────┴──────────┴─────────────────────────────────────┘
```

- 长度字段为**小端序**;CRC32C 覆盖"类型 + 载荷长度 + 载荷"。
- 类型字段本期只使用 `PUT = 1`;**格式上预留批写**(`BATCH = 2`,一条记录含多组 KV),供 P3 事务使用。P1 不实现批写。
- 记录之间不允许有填充字节。

### 5.3 Segment 文件格式

```
┌──────────────────────────────────────────────┐
│ Footer(固定长度,置于文件末尾)              │
│   magic · version · 各区块偏移 · 总行数 · 校验和│
├──────────────────────────────────────────────┤
│ 列块 1(value 列)                            │
│   chunk 0 | chunk 1 | … (每 chunk 4096 行)   │
├──────────────────────────────────────────────┤
│ 列块 0(key 列)                              │
├──────────────────────────────────────────────┤
│ ZoneMap:各列 min / max / 行数                │
├──────────────────────────────────────────────┤
│ Index Block:每 chunk 的首 key + 文件偏移      │
└──────────────────────────────────────────────┘
```

- 本期列块使用**原始编码**(不做字典 / RLE / 压缩),但**结构上按列组织**,以便 P5 直接替换编码方式而不改文件布局。
- Footer 放在文件末尾是为了打开文件时只读尾部即可拿到全部元信息。

### 5.4 MANIFEST 格式

建议用**追加式记录 + 原子切换**:每次变更写一条新记录追加到当前 MANIFEST;达到阈值或启动时重写为新文件并原子更新 `CURRENT`。具体实现方式由实现方给出方案说明。

### 5.5 配置文件格式(0.2 新增)

两个文件放在仓库根目录的 `config/` 下(与 `fe/`、`be/` 同级),语法完全相同:

```
# 注释以 # 开头(整行),空行忽略
data_dir = ./data/BE
port = 9100
memtable_size = 64MB
```

- 一行一项,`key = value`,两侧空白自动裁剪;**没有引号、转义、区块等语法**。
- 容量支持 `64MB` / `1MB` / `32KB` / `1048576`(纯字节数)。
- 解析必须用各语言**标准库手写**:BE 侧不得为此引入任何第三方库(依赖红线)。
- 未知配置项、格式错误(缺 `=`)、取值为空、取值非法 → 启动失败并指明第几行。
- BE 的 `data_dir` 是相对**进程工作目录**解析的(`start-be.sh` 会先 `cd be/`)。
- 默认路径 `./config/be.conf`、`./config/fe.conf` 同样是相对进程工作目录;两个启动脚本会显式传入仓库里的绝对路径,避免受工作目录影响。

## 6. 关键技术决策(本期默认值)

以下几项已按推荐取值,写进规约作为施工默认。**有异议请指出,没异议就照办。**

| # | 决策点 | 取值 | 理由 |
|---|---|---|---|
| K1 | key 编码 | **裸字节**。P1 不做表/索引分区,key 就是用户给的 bytes | 表与索引的编码是上层封装,L S M 本身只认 bytes。这样分层,后面加编码层不用改引擎 |
| K2 | fsync 策略 | **每条 Put 一次 fsync** | 安全优先。组提交(group commit)能大幅提吞吐,但会增加复杂度与丢数据窗口 → 留作后续优化项 |
| K3 | memtable 阈值 | 默认 **64MB**,可配 | 太小会频繁刷盘,太大会拖长恢复时间 |
| K4 | 不可变表数量上限 | **2 个**,超出时前台写等待 | 防止后台刷盘跟不上导致内存爆掉 |
| K5 | 是否本期做 compaction | **不做** | P1 只验证正确性;文件累积的代价可接受 |
| K6 | 列块编码 | **原始编码**(结构按列,编码不压缩) | 布局一次定好算,编码方式 P5 再换 |
| K7 | ZoneMap 粒度 | 每 chunk(4096 行)一份 min/max | 与 P5 的跳块优化共用同一份结构 |
| K8 | 线程模型 | 前台写 goroutine 直接写 memtable;后台单 Flush Worker | 简单;并发写靠跳表的锁粒度 |
| K9 | 日志 | 标准库 `log/slog`,输出到 stdout + 可选文件 | 不引第三方日志库 |
| K10 | 崩溃测试的杀法 | Windows 用 `taskkill /F`,脚本同时支持 `kill -9` | 本机是 Windows,不能用 `kill -9` |
| K11 | 配置载体(0.2) | **`config/be.conf` + `config/fe.conf`**,一行一项 `key = value` | 两个进程的配置各归各的,与 `fe/`、`be/` 同级;手写 k=v 解析,BE 侧零依赖 |
| K12 | 配置与命令行参数的关系(0.2) | **命令行 > 配置文件 > 内置默认值**,参数只覆盖显式给出的项 | 日常改配置改文件即可;测试/临时跑仍能用 `--port`、`--memtable-size` 覆盖(崩溃测试要传 32KB 阈值) |

## 7. 验收标准

| 编号 | 验收项 | 判定 |
|---|---|---|
| **SC-001** | 写入 1000 条随机 KV → 强杀两进程 → 重启 → 逐条校验 | **丢失 0 条**,值完全一致 |
| **SC-002** | 从零到跑通的操作步骤 | 一条命令起 BE、一条命令起 FE(配置读 `config/` 下的文件),照 README 能复现 |
| **SC-003** | 数据目录结构 | 人工可读:`CURRENT`、`MANIFEST-*`、`wal/*.wal`、`sst/*.seg` 均存在且非空 |
| **SC-004** | 写入延迟(内存路径) | P99 < 5 ms(本机,1000 条测量) |
| **SC-005** | 读取延迟(内存命中) | < 1 ms |
| **SC-006** | 恢复 10 万条 WAL | < 30 s |
| **SC-007** | WAL 尾部截断 | BE 正常启动,截断处之后的数据被丢弃,之前的数据可读 |
| **SC-008** | 依赖红线 | `be/go.mod` 中除 grpc / protobuf 外无第三方依赖 |
| **SC-009** | 单元测试 | WAL 编解码、跳表、segment 读写、恢复逻辑均有测试且全绿 |
| **SC-010** | 一键验收 | `scripts/crash-test.sh` 一条命令跑完并输出报告 |

## 8. 边界与异常清单

| 情形 | 期望行为 |
|---|---|
| key 不存在 | `NOT_FOUND` |
| key 为空 | `INVALID_ARGUMENT` |
| value 为空(长度 0) | **允许**,是合法的值 |
| value 含 `\0` / 非 UTF-8 | 正常存取 |
| 单个 value > 1MB | `INVALID_ARGUMENT` |
| 反复覆盖同一 key | 后写覆盖先写;`get` 返回最新值 |
| 同一 key 跨 memtable 与 segment | 返回**较新**的那个(memtable 优先) |
| memtable 恰好写满 | 冻结正常触发,不丢不重 |
| 刷盘进行中进程被杀 | 该 segment 文件不完整 → 恢复时以 MANIFEST 为准丢弃;数据由 WAL 重放补回 |
| WAL 最后一条被截断 | 停止重放并丢弃该条,正常启动 |
| MANIFEST 引用的 segment 丢失 | 跳过 + 记警告,不阻止启动 |
| 数据目录不存在 | 自动创建 |
| 默认配置文件不存在 | 使用内置默认值 + 打印警告,正常启动 |
| 显式 `--config` 指定的文件不存在 | 启动失败,退出码非 0,错误信息含路径 |
| 配置文件有未知配置项 / 缺 `=` / 取值为空 / 取值非法 | 启动失败,错误信息含文件名与行号 |
| 配置文件里的 port 被命令行 `--port` 覆盖 | 以命令行为准,其余项仍取配置文件 |
| 配置文件与内置默认值的取舍 | 文件里没写的键用内置默认值(不因文件存在而清空其它项) |
| 数据目录不可写 | 启动失败,打印明确错误 |
| 端口被占用 | 启动失败,退出码非 0 |
| FE 连不上 BE | 中文明确提示,不打印堆栈 |
| 磁盘写满(可测) | 返回 `INTERNAL`,不产生内存/磁盘不一致 |

## 1. 本轮要做的 5 条(只有这 5 条)

| FR | 要求 | 验收口径 |
|---|---|---|
| FR-716 | 解码复用:投影帧解码不再每行 `new Object[列数]`;复用缓冲与基本类型数组,消除逐行装箱 | 单测覆盖"同一 Plan 连续解 N 行不加分配";结果逐行不变 |
| FR-714 | 排序并行:`ORDER BY` / `sortDistinct` / `sortMergeJoin` 的排序改为"分片内并行排序 + 归并" | 并行度 1 与 >1 结果**逐行同序**;`sort_spill_bytes` 语义不变 |
| FR-713 | 聚合分桶并行:`GROUP BY` 按键分桶、局部聚合、二次合并;`COUNT/SUM/AVG/MIN/MAX/STDDEV/VARIANCE/GROUP_CONCAT` 全覆盖 | 与单线程**逐行同序**(顺序按首次出现或 GROUP BY 键序,必须与现状一致) |
| FR-712 | Hash Join 分桶并行:build 按哈希桶分段并行构建、probe 并行,再按稳定顺序合并 | 与单线程**逐行同序**;LEFT JOIN 的补空行位置不变 |
| FR-715 | 结果集流式:`LIMIT` 命中即停止向上游取数并终止扫描,不再整表物化后才输出 | `LIMIT n` 返回行数与内容不变;大结果集内存不随行数线性增长 |

**排序/聚合/JOIN 的输出顺序是硬要求**:现有 SC-410 / SC-411 / SC-415 与 p5/p6 的断言都是"逐行一致",并行实现必须做确定性归并(按分片序或键序),不许用"集合相等"糊过去。

## 3. 工作方式(上一轮踩过的坑,逐条遵守)

- **禁止派子代理**,所有步骤自己顺序做。
- **禁止用 `nohup` / `disown` / 裸 `&` 起服务**:上一轮这样做把 bash 工具卡死了三次(每次 1~2 小时)。要起服务只用仓库脚本(`bash scripts/start-be.sh --daemon ...` / `bash scripts/tests/p6.1-test.sh`),它们自己负责 daemon 化与 PID 文件;单条 bash 超过 60 秒没返回就换写法。
- 每个步骤做完**立刻**跑构建与单测,不要攒到最后:
  1. `cd fe && mvn.cmd compile`
  2. `cd fe && mvn.cmd test`
  3. `cd be && go build ./... && go vet ./... && go test ./...`(确保没意外碰到 BE)
- 测试环境是**独占**的:任何时刻只跑一个脚本。跑验收脚本前先确认没有残留 `be.exe` / `tangdb.fed.Fed` 进程。

## 4. 实现顺序(由易到难,每步可独立回退)

1. **FR-716 解码复用** —— 改 `ProjectedCodec.decode`,加单测;`mvn.cmd test` 全绿再往下。
2. **FR-714 并行排序** —— 复用现成 `ExecutorService` 思路(参考 `QueryEngine.scanShards` 的线程池写法),并行度取 `options.parallelism()`,=1 时走原路径;结果按分片序归并。
3. **FR-713 聚合分桶并行** —— 局部聚合对象要可合并(注意 `AVG`/`STDDEV`/`GROUP_CONCAT` 的合并语义)。
4. **FR-712 Hash Join 分桶并行** —— build 侧按 hash 分段、probe 侧并行,最后按 build 行序 + probe 行序稳定合并;LEFT JOIN 的补空行逻辑保持。
5. **FR-715 流式结果 + LIMIT 终止** —— 只改 FE 输出链:把"先全量 `Relation.rows` 再输出"改成"逐批取、逐批写";`LIMIT` 满足即停并释放上游扫描。CLI 与 MySQL 协议的回显格式必须完全不变。

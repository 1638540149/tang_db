## 要做的事

**1. `LIMIT <offset>, <row_count>` 与 `LIMIT <row_count> OFFSET <offset>`(FR-549 ~ FR-552 / K100)**

- 现在 `SELECT * FROM t LIMIT 0,1000` 报 `1064`(语法错);图形客户端翻页全靠这个写法。
- Parser:在 `SELECT` 的 `LIMIT` 子句里同时接受三种写法 `LIMIT n` / `LIMIT off,n` / `LIMIT n OFFSET off`;`off`/`n` 必须是非负整数,非法报 `1064` 并指出位置。
- 执行语义(**先过滤 → 再跳过 offset → 再截断 count**),`Executor.select` 里实现;`offset >= 行数` 返回空集不报错;`LIMIT 0,0` 空集。
- 索引路径与全表扫路径行为必须一致(两条路径共用同一处 limit 逻辑)。
- `UPDATE` / `DELETE` 带 `LIMIT` → 明确报 `1235`(不做半实现)。

**2. 虚拟表 `ORDER BY` 放开到多列(FR-553 / K99)**

- 现在 `SELECT ... FROM information_schema.TABLES ORDER BY TABLE_SCHEMA, TABLE_TYPE` 报 `1235`(只支持单列)。
- 支持多列、每列可 `ASC`/`DESC`,按列序依次比较(前一列相等才比下一列)。
- **仍只对 `information_schema.*` 生效**;用户表上的 `ORDER BY` 继续明确报"不支持(归 P5)"(K98/K99 的边界不许破)。

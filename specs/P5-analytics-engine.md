## 1. 目标

P5 把 tang_db 从“能查”推到“查得动”:

1. **列式 segment + 压缩**:segment 按列存 + 自研轻量压缩编码(不引第三方压缩库),列式压缩率与读放大可观测。
2. **向量化执行**:所有算子输入输出是 `batch`(列数组 + 有效性位图),算子间流水线拉取,标量函数按列批量算。
3. **通用查询能力**:`ORDER BY` / `LIMIT ... OFFSET` / 聚合(`COUNT/SUM/AVG/MIN/MAX`、`COUNT(DISTINCT)`)/ `GROUP BY` + `HAVING` / **JOIN**(NLJ、Hash Join)/ 子查询(至少 `IN (子查询)` 与标量子查询)。
4. **谓词与表达式补齐**:`NOT` / `IS [NOT] NULL` / `LIKE` / `BETWEEN` / 算术与比较表达式 / 常用标量函数(§2.8-F-01 的“常用优先”子集)。
5. **Compaction 与版本回收**:分层(leveled)合并、墓碑与被覆盖版本回收、GC 水位按最老活跃快照;写放大 / 读放大**从本期起设门限**。
6. **CSV 批量导入**:走与 WAL 相同的“先日志后数据”通道,断点可续,并给出 E-04 口径的任务元数据。
7. **JSON 半结构化**(设计文档 §2.4-S-08 归本期):`JSON` 列 + `json_extract`,不做路径索引与路径级列存。

**做完能看到**:千万行上 §3.2 那条多表聚合查询秒级出结果(目标 < 3 s);`scripts/tests/p5-test.sh` 一键跑完简化 TPC-H 子集并输出耗时;`data/BE` 的写放大 / 读放大 / 内存峰值 / 恢复时间四项首次给出**带门限**的数字。

## 2. 范围

### 2.1 本期做(按组)

**A 组 · 列式存储与压缩**

| 编号 | 内容 |
|---|---|
| A-1 | segment 的列存布局:每列独立 column chunk,带最小值/最大值/空值计数(**ZoneMap**),按 chunk 建偏移表 |
| A-2 | 自研压缩编码(不引第三方库):**RLE**、**字典编码**(低基数列)、**位打包/整数差分**(整数列)、**前缀截断**(字符串列);每 chunk 自选编码,编码类型写进 chunk 头 |
| A-3 | 压缩往返无损:任意列类型、任意值(含 `NULL`、空串、极值)解压后与写入值逐字节相等 |
| A-4 | 压缩率可观测:`SHOW TABLE STATUS` / `information_schema.TABLES` 的 `DATA_LENGTH` 由 NULL 改为真值;新增 `SHOW SEGMENTS`(自有诊断语句)给出每 segment 的列数、行数、原始字节、压缩后字节、压缩率、编码分布 |
| A-5 | **点查行级定位**(外部评审必答项 P5,见 §7):Index Block 按 chunk 首 key 二分 + 块内偏移数组 + 块级布隆过滤,消除块内线性查找 |

**B 组 · 向量化执行**

| 编号 | 内容 |
|---|---|
| B-1 | 统一 batch 结构 `{列数, 行数, 每列数据数组 + 有效性位图}`,一次至少 1024 行(pull 模型,算子间不物化中间结果) |
| B-2 | 扫描 / 过滤 / 投影 / 聚合 / 排序 / 连接 六类算子全部改为 batch 接口;`NULL` 一律走位图运算,不按行判断 |
| B-3 | 标量函数按列批量求值(一次处理一整列,不逐行调用) |
| B-4 | 谓词下推到扫描层:能下推的比较 / `IN` / `IS NULL` / `BETWEEN` 在 chunk 层先用 ZoneMap 剪枝,再在 batch 内求值 |

**C 组 · 排序与分页**

| 编号 | 内容 |
|---|---|
| C-1 | `ORDER BY <列> [ASC\|DESC] [, ...]`(多列,用户表),`NULL` 排序口径见 K105 |
| C-2 | `LIMIT n` / `LIMIT off, n` / `LIMIT n OFFSET off` 在排序后语义正确(先排序 → 再跳过 → 再截断) |
| C-3 | `ORDER BY ... LIMIT n` 走 **TopN 堆**,不物化全量排序结果;数据超内存的纯排序走外部归并(分片排序 + 多路归并) |
| C-4 | 排序稳定性:等值行之间的相对顺序不承诺,但**同一查询重复执行结果集内容一致** |

**D 组 · 聚合**

| 编号 | 内容 |
|---|---|
| D-1 | `COUNT(*)` / `COUNT(col)` / `SUM` / `AVG` / `MIN` / `MAX`,空输入口径:除 `COUNT` 外一律 `NULL`;`COUNT` 返回 0 |
| D-2 | `GROUP BY`(单列与多列)+ `HAVING`(在分组后过滤,可引用聚合结果) |
| D-3 | `COUNT(DISTINCT x)`;`SUM(DISTINCT)` / `AVG(DISTINCT)` 归 P6(见 §2.2) |
| D-4 | 无 `GROUP BY` 的聚合返回**恰好一行**(空表也要一行) |
| D-5 | 聚合的 `NULL` 语义:`SUM/AVG/MIN/MAX` 跳过 `NULL`;`GROUP BY` 把 `NULL` 当作一个独立分组 |

**E 组 · JOIN 与子查询**

| 编号 | 内容 |
|---|---|
| E-1 | `INNER JOIN ... ON a.x = b.y`(等值连接);至少支持两表,三表串联必须能跑 |
| E-2 | 物理实现:小表侧建哈希表(`Hash Join`)+ `Nested Loop Join` 兜底(非等值条件);本期**不做** `Sort-Merge Join`(归 P6) |
| E-3 | `LEFT JOIN`:右表无匹配时右列补 `NULL` |
| E-4 | 子查询:`IN (SELECT ...)` 与标量子查询 `(SELECT ...)`(返回单值;多行时按 K108 报错) |
| E-5 | 连接列类型必须可比较;不可比较时报类型错误,不得静默强转 |

**F 组 · 谓词与表达式**

| 编号 | 内容 |
|---|---|
| F-1 | 谓词:`NOT`、`IS NULL` / `IS NOT NULL`、`LIKE`(`%` / `_`,不区分大小写口径见 K106)、`BETWEEN ... AND ...`、三元逻辑(`NULL` 参与比较结果为 `UNKNOWN`,过滤时按“不通过”处理) |
| F-2 | 表达式:算术(`+ - * / %`)、比较、`AND/OR/NOT` 任意嵌套、括号、`CASE WHEN ... THEN ... ELSE ... END` |
| F-3 | 标量函数(§2.8-F-01 常用子集):`ABS/ROUND/CEIL/FLOOR/MOD`、`LENGTH/UPPER/LOWER/SUBSTR/CONCAT/TRIM/REPLACE`、`COALESCE/IFNULL/CAST`;每个函数要有单测,含 `NULL` 入参 |
| F-4 | `SELECT` 投影里可以有表达式与函数,列名口径:有别名用别名,否则用表达式原文(见 K107) |

**G 组 · Compaction、版本回收与性能门限**

| 编号 | 内容 |
|---|---|
| G-1 | 分层(leveled)compaction:某层文件数 / 总字节超阈值即触发,合并到下一层;同一层内 key 范围不重叠 |
| G-2 | 合并时:多路归并、丢弃被覆盖的旧版本、丢弃可回收墓碑、写出新 segment 并**原子更新 MANIFEST**;旧 segment 在新 MANIFEST 落盘后才删 |
| G-3 | GC 水位 = **当前最老活跃快照序号**;只回收 `commit_ts < 水位` 的版本,等于水位必须保留;水位不持久化,重启后 = 当前最大 `commit_ts` |
| G-4 | 墓碑只有在“其下所有旧版本都可回收”时才随 compaction 删除 |
| G-5 | 写放大 / 读放大 / 内存峰值 / 恢复时间四项**首次设门限**(数值见 §3.3 与 SC-356);不达标要在验收报告里给原因与归属期次,不许直接改门限 |

**H 组 · CSV 批量导入与工具**

| 编号 | 内容 |
|---|---|
| H-1 | `scripts/tools/csv-import`(或 `fed --import`)按表导入 CSV:首行列名映射,类型转换失败报**行号 + 列名**,整批失败不留半截数据 |
| H-2 | 导入走与普通写入相同的“先日志后数据”通道(WAL → fsync → memtable),分批提交,批大小可配 |
| H-3 | 断点可续:导入进度(文件偏移 / 已提交行数)写进一张导入状态表,重跑同一条命令从断点续 |

**I 组 · JSON 半结构化与函数补齐(2026-10-27 追加,依据 §2.4-S-08 / §2.8-F-02)**

| 编号 | 内容 |
|---|---|
| I-1 | `JSON` 列类型(BSON 式二进制子集)+ `json_extract` 路径取值;不做路径索引 / 路径级列存 / 整文档替换 |
| I-2 | 聚合补齐:`STDDEV` / `VARIANCE`(总体口径)、`GROUP_CONCAT`(上限 1MB) |
| I-3 | 日期函数 `YEAR/MONTH/DAY`;`NOW/DATE_ADD/DATE_DIFF` 归 P12 |
| I-4 | CSV 导入任务元数据对齐 E-04 最小任务模型 |

### 2.2 本期明确不做(及归属)

| 不做 | 归属 / 理由 |
|---|---|
| **统计信息 / CBO 代价模型 / 连接顺序选择** | **P6**。本期 JOIN 选型按固定规则(小表建哈希),不看统计 |
| `Sort-Merge Join`、超大规模外存 JOIN | P6(与 CBO 一起决定何时值得) |
| 窗口函数、`GROUPING SETS` / `ROLLUP` / `CUBE` | 不做,归 **P14 之后的候选**(登记在设计文档,不占 P6) |
| `UNION` / `UNION ALL` / `INTERSECT` / `EXCEPT` | **P6**(集合运算与计划层一起做)。本期明确报 1235 |
| 相关子查询(外层列进内层)、`EXISTS` / `ANY` / `ALL` | **P6** |
| 表达式 / 路径索引、函数索引下推 | **P11 之后** |
| JSON 的**路径索引 / 路径级列存 / 整文档替换更新** | 不做(§2.4-S-08 明文);JSON 类型本身与 `json_extract` **本期做**(FR-609/610/611) |
| `NOW()` / `DATE_ADD` / `DATE_DIFF`、`TIMESTAMP` / `DATETIME` 类型 | **P12**(空间与时序);本期只做 `YEAR/MONTH/DAY`(FR-613) |
| 向量化 UDF / AI 函数 | **P7** |
| 并行执行(多线程 / 多分片流水线) | **P8 之后**;本期单线程流水线,靠 batch 与列存拿性能 |
| 压缩的“可查询编码”(如不完整解压直接过滤) | 不做:本期先保证**无损往返 + 压缩率**,向量化谓词改写归 P6/P8 |
| 存储过程 / 触发器 / 视图 | 不做(沿用 P4 §2.2) |
| `ALTER TABLE` 任何形态 | **P4 之后**仍未做,维持原状(P5 不碰) |

### 2.3 保证 / 不保证

- **保证**:所有查询结果与“朴素逐行实现”**逐行一致**(对拍是硬性验收手段);压缩往返无损;compaction 前后同一查询结果不变;崩溃重启后已提交数据与索引、压缩 segment 一致。
- **不保证**:性能数字在所有机器上达标(给目标与条件模板,不达标要解释);并行加速(本期无并行);`ORDER BY` 等值行相对顺序;超大排序(超磁盘可用空间)的行为。

## 4. 需求(FR)

### 4.1 列式与压缩(FR-563 ~ FR-570)

| 编号 | 需求 |
|---|---|
| FR-563 | segment 按列存储:每列独立 chunk,chunk 头含 `encoding / 原始字节 / 压缩后字节 / 行数 / min / max / null_count` |
| FR-564 | 压缩编码至少实现 RLE / 字典 / 位打包(整数差分)/ 前缀截断四种;每 chunk 按“体积最小”自选,选择结果写入 chunk 头 |
| FR-565 | 压缩往返无损:随机值、极值(`INT_MIN`/`INT64_MAX`)、`NULL`、空串、超长串(≤ 列长上限)全部逐字节相等 |
| FR-566 | `SHOW SEGMENTS`(自有诊断)输出:segment 文件、列、行数、原始字节、压缩后字节、压缩率、各编码命中数 |
| FR-567 | `SHOW TABLE STATUS` / `information_schema.TABLES.DATA_LENGTH` 由 `NULL` 改为真实字节数(与 FR-566 口径一致) |
| FR-568 | Index Block:每 chunk 记录首 key,块尾偏移数组;按 key 二分定位到 chunk 后再二分到行,禁止块内线性查找 |
| FR-569 | chunk 级布隆过滤(可选开启,默认开)用于等值点查;布隆误判不得导致**漏行** |
| FR-570 | 列裁剪:查询只读用到的列 chunk;`SELECT *` 除外。`EXPLAIN` 要能显示实际读取的列 |

### 4.2 向量化执行(FR-571 ~ FR-576)

| 编号 | 需求 |
|---|---|
| FR-571 | batch 结构:`{列数, 行数, 每列 values 数组 + validity 位图}`,默认批 1024 行(可配) |
| FR-572 | 算子统一 `next(batch)` pull 接口:Scan / Filter / Project / Aggregate / Sort / Join 全部实现该接口,算子间不物化中间结果 |
| FR-573 | `NULL` 只用位图表示;所有算子对 `NULL` 的处理与三值逻辑一致 |
| FR-574 | 标量函数按列求值,单次调用处理整列;含 `NULL` 入参时输出位图对应位为 0 |
| FR-575 | 扫描层谓词下推:比较 / `IN` / `IS NULL` / `BETWEEN` 先在 chunk 用 ZoneMap 剪枝,再在 batch 内求值 |
| FR-576 | 向量化路径与逐行路径**结果一致**:同一查询在两条路径上的结果集必须逐行相等(对拍单测) |

### 4.3 排序与分页(FR-577 ~ FR-580)

| 编号 | 需求 |
|---|---|
| FR-577 | `ORDER BY` 支持多列、每列独立 `ASC/DESC`;表达式排序本期不做(只支持列名与别名) |
| FR-578 | 分页语义:先 `WHERE` → 再 `ORDER BY` → 再跳过 `offset` → 再截断 `n`;`offset` 越界返回空集不报错 |
| FR-579 | `ORDER BY ... LIMIT n` 用 TopN 堆,内存占用与 `n` 相关、与表行数无关 |
| FR-580 | 纯排序(无 `LIMIT`)超内存时走外部归并(分片排序落临时文件 + 多路归并),临时文件在查询结束后清理 |

### 4.4 聚合(FR-581 ~ FR-586)

| 编号 | 需求 |
|---|---|
| FR-581 | `COUNT(*)` / `COUNT(col)` / `SUM` / `AVG` / `MIN` / `MAX`;空输入:`COUNT` = 0,其余 `NULL` |
| FR-582 | `GROUP BY` 单列与多列;分组键含 `NULL` 时 `NULL` 自成一组 |
| FR-583 | `HAVING` 在分组后过滤,可引用聚合结果与分组键;`HAVING` 不得出现非分组列(报错,不静默) |
| FR-584 | `COUNT(DISTINCT col)`:按值去重后计数,`NULL` 不计入 |
| FR-585 | 无 `GROUP BY` 的聚合恒返回一行(空表也要一行) |
| FR-586 | 聚合列与投影列混用(如 `SELECT city, SUM(x) FROM t GROUP BY city`):非分组非聚合列必须报错 |

### 4.5 JOIN 与子查询(FR-587 ~ FR-592)

| 编号 | 需求 |
|---|---|
| FR-587 | `[INNER] JOIN ... ON <等值条件>`;两表与三表串联必须可用 |
| FR-588 | `LEFT JOIN`:右表无匹配补 `NULL`;`WHERE` 里对右表列的过滤在连接后生效(不做下推优化,结果必须正确) |
| FR-589 | 物理实现:等值条件走 Hash Join(小表侧建表,大小按“行数 × 行宽”估算),非等值条件走 Nested Loop |
| FR-590 | `IN (SELECT ...)`:子查询先求值成集合再半连接;空集合 → 空结果集 |
| FR-591 | 标量子查询:返回 0 行 → `NULL`;返回多行 → 报错(码见 K108) |
| FR-592 | 连接列类型不可比较时明确报类型错误;`NULL` 连接键不匹配(标准三值逻辑) |

### 4.6 谓词、表达式与函数(FR-593 ~ FR-598)

| 编号 | 需求 |
|---|---|
| FR-593 | 谓词:`NOT`、`IS NULL`、`IS NOT NULL`、`LIKE`(`%`/`_`,含转义字符)、`BETWEEN a AND b`(闭区间) |
| FR-594 | 三值逻辑:`NULL` 参与比较得 `UNKNOWN`;`WHERE` 只放行 `TRUE`;`NOT UNKNOWN` 仍是 `UNKNOWN` |
| FR-595 | 算术:`+ - * / %`;除零 → `NULL`(不报错,口径见 K109);整数溢出按 64 位回绕并在结果中保持一致 |
| FR-596 | `CASE WHEN ... THEN ... [ELSE ...] END`,以及 `COALESCE` / `IFNULL` / `CAST`(支持 `INT/BIGINT/DOUBLE/VARCHAR`) |
| FR-597 | 字符串函数:`LENGTH / UPPER / LOWER / SUBSTR / CONCAT / TRIM / REPLACE`;数值函数:`ABS / ROUND / CEIL / FLOOR / MOD` |
| FR-598 | 每个函数至少一条单测,覆盖正常值、`NULL` 入参、边界值(空串、负数、超长) |

### 4.7 Compaction、版本回收与门限(FR-599 ~ FR-604)

| 编号 | 需求 |
|---|---|
| FR-599 | leveled compaction:`L0` 文件间 key 可重叠,`L1+` 层内不重叠;每层容量比 10:1(参数可配) |
| FR-600 | 触发条件:某层文件数或总字节超阈值;阈值写配置,默认值见 §5.4 |
| FR-601 | 合并流程:选文件 → 多路归并 → 丢弃 `commit_ts < 水位` 的旧版本与可回收墓碑 → 写新 segment → fsync → **原子更新 MANIFEST** → 删旧文件 |
| FR-602 | GC 水位 = 最老活跃快照;等于水位的版本必须保留;水位不持久化,重启后 = 最大 `commit_ts` |
| FR-603 | compaction 期间查询与写入不被阻塞(读旧 MANIFEST 视图),合并失败要能整体回退(旧 segment 未被删) |
| FR-604 | 写放大 / 读放大 / 内存峰值 / 恢复时间四项按 §3.3 门限验收,并记录机器条件模板 |

### 4.8 CSV 导入(FR-605 ~ FR-608)

| 编号 | 需求 |
|---|---|
| FR-605 | 导入命令:目标表 + CSV 文件 + 批大小;首行为列名,列名与表列名不匹配 → 报错并列出差异 |
| FR-606 | 类型转换失败:报**行号 + 列名 + 原值**,整批回滚,不留半截数据 |
| FR-607 | 导入走 WAL → fsync → memtable 通道,分批提交;每批提交后进度落盘 |
| FR-608 | 断点续传:重跑同一命令跳过已提交行;同一文件重复导入不产生重复行(按主键去重,口径见 K110) |

### 4.9 JSON 半结构化与函数补齐(FR-609 ~ FR-614,2026-10-27 追加)

> 依据设计文档 §2.4-S-08 与 §21 判定表(#3):**`JSON(Binary JSON)` 归 P5**;§2.8-F-02 把 `COUNT(DISTINCT)`、`STDDEV/VARIANCE`、`GROUP_CONCAT` 一并建议 P5。本节把它们纳入本期。

| 编号 | 需求 |
|---|---|
| FR-609 | `JSON` 列类型:值为 BSON 式二进制编码(长度前缀 + 类型标记 + 字段名 + 值),写入与读取往返无损(解码再编码后语义等价);列存里 JSON **整体当一列**,不做路径级列存 |
| FR-610 | `json_extract(doc, '$.a.b')` / `json_extract(doc, '$.arr[0]')`:路径取值,支持对象嵌套与数组下标;路径不存在或类型不符返回 `NULL`(不报错) |

| FR-612 | 聚合补齐:`STDDEV(x)` / `VARIANCE(x)`(口径见 K119)、`GROUP_CONCAT(x)`(默认分隔符 `,`,长度上限见 K118);三者都要跳过 `NULL` |
| FR-613 | 日期函数只做 `YEAR(d)` / `MONTH(d)` / `DAY(d)`(`DATE` 入参,返回整数);`NOW()` / `DATE_ADD` / `DATE_DIFF` 归 **P12**(依赖 `TIMESTAMP`/`DATETIME` 类型,见 §2.4.1) |

## 5. 数据与格式

### 5.1 压缩 chunk 头(每个 column chunk 一段)

```
[列ID 2B][编码 1B][行数 4B][原始字节 4B][压缩后字节 4B]
[min 值(按列类型定长,可空)][max 值(同上)][null_count 4B]
[偏移数组 4B × chunk 数][压缩后的数据]
```

- 编码枚举:`0=RAW`、`1=RLE`、`2=DICT`、`3=BITPACK`(整数差分)、`4=PREFIX`(字符串前缀截断)
- 值编码沿用 P1~P4 的保序编码,压缩在**编码后的字节**上做,因此比较语义不变

### 5.2 batch 结构

```
Batch {
  int columns; int rows;
  Column[] cols;   // 每列: Object[] 或 定长数组 + long[] validity 位图(bit i = 良 1 / NULL 0)
}
```
- 默认 `batch_size = 1024`,配置项 `query_batch_rows`

### 5.3 CSV 导入状态表

```
sys_import_state(import_id, table_id, file_path, file_size, file_mtime,
                 last_offset, last_row_no, committed_rows, updated_at)
```

### 5.4 新增配置(`config/be.conf` / `config/fe.conf`)

| 键 | 默认 | 含义 |
|---|---|---|
| `query_batch_rows` | 1024 | 向量化批行数 |
| `compaction_l0_files` | 4 | L0 触发合并的文件数 |
| `compaction_level_ratio` | 10 | 层容量比 |
| `compaction_level_max_bytes` | 256MB | 单层容量上限 |
| `compaction_bloom_enabled` | true | chunk 级布隆过滤 |
| `sort_spill_bytes` | 64MB | 排序溢写阈值(超了走外部归并) |
| `csv_import_batch_rows` | 5000 | 导入批大小 |

## 6. K 决策表(每项带推荐值 + 理由)

| 编号 | 决策点 | 推荐值 | 理由 |
|---|---|---|---|
| **K103** | 压缩库 | **自己写** RLE / 字典 / 位打包 / 前缀截断 | 依赖红线不允许第三方压缩库;这四种覆盖整数与字符串的绝大多数场景,收益已经足够 |
| **K104** | compaction 策略 | **leveled(分层)** | 设计文档 §6.4 已定;读放大可控是读放大门限(≤ 2 segment)的前提 |
| **K105** | `ORDER BY` 的 `NULL` 位置 | **升序时 `NULL` 在最前,降序时在最后**(MySQL 口径) | 与客户端预期一致;要反过来只需改一处比较器 |
| **K106** | `LIKE` 大小写 | **不区分大小写**(`utf8mb4_general_ci`) | 与 P4 声明的排序规则一致;区分大小写要等 `_bin` 排序规则真正落地 |
| **K107** | 表达式投影的列名 | 有别名用别名,否则用**表达式原文**(如 `COUNT(*)`、`a + b`) | 客户端按列名取值;MySQL 同口径,避免结果集列名为空 |
| **K108** | 标量子查询返回多行 | 报 **1242**(`Subquery returns more than 1 row`) | MySQL 同码,客户端已有处理分支 |
| **K109** | 除零 | 返回 `NULL`(不报错) | MySQL 默认行为;报错会让整条查询失败,客户端体验差 |
| **K110** | CSV 重复导入 | 按**主键去重**(`INSERT OR IGNORE` 语义),不报错 | 断点续传会重放最后一批;报错会让人反复修数据 |
| **K111** | 向量化范围 | 本期**单线程流水线**,不做并行 | 并行要处理分片、合并与顺序,归 P8;单线程 + 列存已能达成 < 3 s 目标 |
| **K112** | JOIN 选型依据 | 按**行数 × 行宽估算**选小表建哈希,不看统计信息 | CBO 归 P6;固定规则可解释、可回归 |
| **K113** | compaction 与查询的隔离 | 读**旧 MANIFEST 视图**,不阻塞 | 避免 compaction 抖动影响在线查询 |
| **K114** | 临时文件位置 | `data/BE/tmp/`,查询结束即删,启动时清理残留 | 崩溃后残留临时文件不得被当成有效 segment |
| **K115** | 点查优化顺序 | 先 Index Block 二分(FR-568),再布隆(FR-569) | 二分是确定性收益,布隆是概率收益;先做确定的 |
| **K116** | 外部评审必答(点查行级定位)的落地 | 见 §7,按 chunk 二分 + 块内偏移数组 + 布隆三层 | 直接回应设计文档 §11 的“没有行级索引”技术债 |
| **K117** | JSON 编码 | **BSON 式二进制子集**(标量/对象/数组,整数/小数/字符串/布尔/`NULL`),不做路径级列存、不做路径索引、不做整文档替换式更新 | 设计文档 §2.4-S-08 明文的三条“不做”;子集足够覆盖 `json_extract` 与多模态元数据(P11) |
| **K118** | `GROUP_CONCAT` 上限 | 默认分隔符 `,`,结果上限 **1MB**,超长截断 + 告警计数 | 不设上限会让内存不可控;告警而不是报错,兼容 MySQL 的宽松口径 |
| **K119** | 方差/标准差口径 | 默认**总体**方差 `VARIANCE` / `STDDEV`;样本版 `VAR_SAMP` / `STDDEV_SAMP` 归 **P6** | 只做一套口径避免二义;样本版等 P6 与统计信息一起做 |

> 想换任何一项就一句话:K105 的 `NULL` 位置、K106 的大小写、K109 的除零口径都是**单点可切换**的。

## 7. 外部评审必答项:P5 的点查行级定位(正面回答)

`specs/README.md` 把“点查路径行级定位”挂给 P5,这里正面回答:

| 问 | 答 |
|---|---|
| 现状(P1~P4)是什么 | ZoneMap 逐 chunk 过滤 → 命中 chunk 解 key 列 → **块内线性查找**,没有行级索引 |
| P5 补什么 | ① Index Block:每 chunk 记录首 key + 块尾偏移数组,按 key **二分**定位 chunk 与行;② chunk 级**布隆过滤**(等值点查先排除不可能命中的 chunk);③ 列裁剪,点查只读 key 列与投影列 |
| 不做什么 | 不做独立 B+ 树/索引文件(“索引就是同一引擎里的有序 key”,§7.1 已定);不引第三方索引库 |
| 怎么验 | 单测:100 万行 1 万次随机点查,断言“触碰 chunk 数 ≤ 2、触碰 segment 数 ≤ 2”;性能:点查 P99 < 10 ms 不退化(SC-357) |

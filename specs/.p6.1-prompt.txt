## 分步实现顺序

**第 1 步 · 开关与配置骨架(FR-718 / FR-723)**
- `fe.conf` 增 `query_parallelism`、`pushdown_enabled`、`scan_batch_rows`、三档 `rpc_*_deadline_seconds`;`be.conf` 增 `wal_buffer_bytes`、`group_commit_max_batch`、`group_commit_max_wait_ms`。非法值启动失败并指出行号。
- 默认值按 §5.2;**此步不改变任何行为**(开关默认关或等价于现状),`mvn.cmd test` + 既有脚本回归必须绿。

**第 2 步 · proto 增量(FR-720 / FR-721 / FR-725)**
- `ScanRequest` 加 `column_mask=6` / `column_slots=7` / `row_frame=8` / `predicate=9` / `columnar_result=10`;`RowBatch` 加 `columnar_block=4`。只加字段,不改既有字段语义。
- `scripts/gen-proto.sh` 重生成,两侧桩代码一并纳入工作区。BE 先做**透传**(收到字段但按旧路径返回),断言"行为与 P6 完全一致"。

**第 3 步 · 写路径 A:批量冲突检测(FR-693 ~ FR-695)**
- 写集按用户键排序去重(同 key 保留最后一次写)→ 单次区间扫描归并 → 语义不变(`latest > snapshot` 即冲突,返回首个冲突 key)。
- `go test -bench` 固化:1,000 行批 + 2MB memtable ≤ 5ms;单测覆盖"同批同 key 三条 → 最后写赢"。

**第 4 步 · 写路径 B:惰性 memtable 游标(FR-696 / FR-697)**
- 跳表下降实现 `Seek`,不拷贝整表;创建时记写计数水位,越水位后 Next/Seek 返回 `unsafe` 错误;保留 `IteratorSnapshot()`(拷贝语义)给长生命周期调用方。
- `go test -race` 跑"遍历中并发写"用例,并断言 `unsafe` 被真实触发一次。

**第 5 步 · 写路径 C:group commit + 缓冲池(FR-698 ~ FR-700)**
- fsync 世代计数:事务返回 OK 前必须等到"覆盖它的世代"完成 fsync;`group_commit_max_batch` / `group_commit_max_wait_ms` 生效。
- WAL 追加复用缓冲;`commitMu` 只包住"排序 → 取号 → 追加"。
- 崩溃注入补两点:`fsync 分组中间`、`fsync 完成后未回包`,由 `tmp/p6.1-test` 的强杀用例断言"已回 OK 的一条不丢,未回 OK 的不可见"。

**第 6 步 · 读路径 D:列投影 + 列式块(FR-701 / FR-702 / FR-707 / FR-710)**
- FE 计算列槽表与行框架参数(`[nullmap][len][bytes]×n`),BE 按字节偏移切片,只回选中列;`columnar_block` 走"原始字节 + 偏移数组"。
- `pushdown_enabled=false` 时必须走原全行路径且结果逐行一致(先做这条回退,再做收益)。

**第 7 步 · 读路径 E:谓词字节码 + 分片(FR-703 ~ FR-705)**
- 栈式字节码:操作码 `EQ/NE/LT/LE/GT/GE/IS_NULL/IS_NOT_NULL/BETWEEN/IN/AND/OR/NOT`,参数 = 列槽号 + 保序编码后的字面量字节;BE 只做字节比较,不感知类型。
- `JSON` 列不下推(留给 FE 残余过滤)。分片用现有 `start_key/end_key`,不新增字段。
- 等价性单测:同一谓词 FE 求值 vs BE 下推求值逐行一致(覆盖 NULL 三值/边界/空串/超长串/类型混合)。

**第 8 步 · 读路径 F:剪枝与预读(FR-706 / FR-708 / FR-709)**
- ZoneMap/布隆按列判定;`SHOW SEGMENTS` 增"剪枝命中 / 跳过 chunk 数";`scan_batch_rows` 自适应(1,024~8,192);segment 预读(只读)。

**第 9 步 · FE 并行扫描(FR-711)**
- 按 key 范围切 N 片并发拉取(`query_parallelism`,默认 `min(8, CPU)`),按片序归并;`query_parallelism=1` 时执行路径必须与 P6 完全一致。

**第 10 步 · FE 算子并行 + 流式结果(FR-712 ~ FR-717)**
- Hash Join build/probe 并行;聚合按分组键分桶并行后二次合并(`COUNT/SUM/AVG/MIN/MAX/STDDEV/VARIANCE/GROUP_CONCAT` 全覆盖);排序分片内并行 + 归并;结果集流式写 socket,`LIMIT` 命中即向上游取消;解码复用缓冲与基本类型数组;`EXPLAIN` 增"并行/批/下推"行。

**第 11 步 · 验收脚本与门限(FR-726 ~ FR-730)**

## 硬约束(违反即返工)

- **依赖红线**:BE 只允许 `grpc` / `protobuf`;FE 不得引第三方 SQL 解析/统计/压缩/并发库(线程池用 JDK 自带)。
- **先日志后数据**:group commit 也必须"返回 OK ⇒ 已 fsync";不许用异步刷盘换吞吐。
- **磁盘格式不变**:WAL 记录布局、segment/chunk、MANIFEST、系统表都不动,不需要迁移。
- **`proto` 只加字段**:不得出现表名/列名/类型名/SQL;BE 只认"列序号 / 偏移 / 操作码 / 字节"。
- **结果不变**:`pushdown_enabled=false` + `query_parallelism=1` 时与 P6 逐行一致;任何"会被估算或并行改变结果集内容与行序"的写法一律禁止。
- **`optimizer_enabled` 与本期两个开关互不影响**,四种组合都要能跑。

## 不要做(超范围即返工)

分布式 / 多节点;`VECTOR`/HNSW/推理下推(P7);自适应优化与智能索引(P14);表达式/函数/路径索引(P11 之后);窗口函数与 `ROLLING`/`CUBE`;`EXPLAIN ANALYZE`、慢查询、监控、备份、Web 控制台(P8 功能项);物化视图/查询缓存;跨段压缩编码改造;表达式级下推(`a+b > c`,只做单列比较);自动 `ANALYZE`。

## 本机口径(踩过的坑,别重踩)

- `mvn` 一律 `mvn.cmd`;Java 中文输出要 `-Dfile.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8`。
- **禁止 `nohup xxx &` 这种不带重定向的后台启动**:后台子进程会继承调用方的 stdout,导致命令永不返回(上一期就是这么挂死两次的)。要起服务只能:
  `"$BIN" --config=... >"$LOG" 2>&1 </dev/null &`,或直接复用 `scripts/start-be.sh --daemon` / `scripts/start-fe.sh --daemon`。
- **不要动 9100 上的 BE 与 3406 上的 fed**(所有者日常环境);测试只用自己的端口与 `tmp/<脚本名>/data`。
- 已知端口占用:9110(crash)、9200/9291/9406(p2)、9600/9691/9706(p3)、9700/9716/9791(p5)、9800/9806/9891(p35)、9900/9906/9991(p4)、9950/9956/9961(p6)。**本期用 9940/9946/9951**。
- 同一时刻只跑一套测试脚本;嵌套调用别的脚本前先停自己起的 BE/fed 并 `kill_stale_tests`(只匹配 `tmp/` 下的进程)。
- 强杀后重启前必须 `wait_port_free <port>` 轮询到空闲,否则周期性假红。
- `ps -W` 第 4 列才是 WINPID(netstat 第 5 列);kill 前核对 `ExecutablePath`,别按进程名一把杀 `java.exe`(本机有 IDEA 子进程)。

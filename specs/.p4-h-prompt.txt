## 要做的事

**1. `COUNT(*)` 接受可选别名(FR-555 / K102)**

- 现在 `fe/src/main/java/com/wangyu/tangdb/parser/Parser.java` 的 `parseSelect` 里,`countStar` 分支吃 `COUNT` `(` `*` `)` 后直接 `expectKeyword("FROM")`,`AS 别名` 会被判语法错。
- 改:与普通列的别名处理走同一套(带不带 `AS` 都收,别名走 `expectIdentifier`),AST 里别为它单开一条路径(`Ast.Select` 若需加字段,就用与 `Ast.Item.alias` 同义的字段名)。
- `fe/src/main/java/com/wangyu/tangdb/execute/MetaCommands.java` 的 `informationSchema(Ast.Select)`:`countStar` 时结果列名 = 别名,没有别名时仍为 `COUNT(*)`。
- 边界不变:用户表上的 `COUNT(*)`(带不带别名)继续报 1235(FR-554 / H-5)。

**2. 单包多语句(FR-556 ~ FR-558 / K101)**

- SQL 入口(`fe/src/main/java/com/wangyu/tangdb/execute/SqlEngine.java`)把一条文本按**顶层分号**切成 N 条,逐条走**既有**单条路径(兼容层 + Parser + Executor 都不改),对外返回结果列表。
- 切分必须感知:单引号 / 双引号 / 反引号、`--` 行注释、`#` 行注释、`/* */` 块注释;里面的分号不切。连续分号与尾随分号产生空语句 → 忽略、不报 1064。转义(如 `''`)要正确跳过。
- 一条失败立即停(FR-558):只回该条的错误包,后面不执行,连接保持。错误码/文案与单条执行时完全一致。
- 回包(`fe/src/main/java/com/wangyu/tangdb/protocol/mysql/ConnectionHandler.java`):
  - 客户端握手声明了 `CLIENT_MULTI_STATEMENTS`(能力位常量已在 `Protocol` 里)→ 逐条回结果集/OK,非最后一条的结束包带 `SERVER_MORE_RESULTS_EXISTS`(0x0008),最后一条不带;
  - **未声明** → 只回**最后一条**语句的结果(前面的照常执行、结果丢弃),绝不追加多余结果集(会协议错位);
  - 服务端**不主动置** `CLIENT_MULTI_STATEMENTS` 能力位(FR-434 原文不变);
  - 单条语句的报文序列必须与今天**逐字节一致**(不许因为走批路径而多带状态位)。
- 协议层不许出现任何 SQL 语义判断(引号/分号识别是 SQL 词汇层,放 `SqlEngine` 侧;AGENTS.md 红线)。

- 现状:`SHOW PROCEDURE STATUS WHERE Db = 'def'` 报 1235(Navicat 打开每个库都会发一条)。
- 要求:接受 `SHOW PROCEDURE STATUS`、`SHOW FUNCTION STATUS`、`SHOW FUNC STATUS`,可带 `LIKE '<pat>'` 与 `WHERE <cond>`;返回 11 列空集:Db / Name / Type / Definer / Modified / Created / Security_type / Comment / character_set_client / collation_connection / Database Collation(与 `SHOW ROUTINES` 的列口径一致)。
- `WHERE` 过滤走现有 SHOW 过滤路径(列名与输出列名一致);过滤到不存在库 / LIKE 无匹配 → 空集不报错。
- 不实现真正的存储过程/函数(仍是空集),`SHOW CREATE PROCEDURE` 保持报不支持。
